# PRD — Security Champions Assistant

## 1. Overview

### 1.1 Project Name (suggestion)
**ChampionForge** *(alternatives: SecChampAI, ChampionOps, ChampCraft)*

### 1.2 Executive Summary
An application that helps organizations build, run, and mature Security Champions
programs, using the **OWASP Security Champions Guide** (10-principle Manifesto +
official checklists) as its backbone, and adding an AI layer to personalize training,
assess program maturity, and generate executive reports.

### 1.3 Problem
Security Champions programs often fail or dissolve because of:
- Lack of structure and clear tracking metrics.
- Generic training, not adapted to each champion's technical stack.
- Difficulty for the "program captain" to report value/ROI to leadership.
- Absence of tools connecting the OWASP theoretical guide to day-to-day practice.

### 1.4 Product Goal
Provide an open-source tool that:
1. Assesses the maturity of a Security Champions program based on the 10 OWASP
   principles.
2. Generates action plans and checklists customized per phase (recruitment,
   development, retention).
3. Creates training tracks and study materials customized by tech stack, using AI.
4. Produces executive reports that justify investment in the program.

### 1.5 Licensing and Attribution (important)
The OWASP Security Champions Guide content is licensed under **CC BY-SA 4.0**.
- Any derived content (checklists, adapted text) distributed by the app must keep a
  compatible license (share-alike) and visible credit to OWASP and the original project
  (`securitychampions.owasp.org`).
- The app must keep an `ATTRIBUTION.md` page in the repository citing the source and
  license.
- Content **generated by AI** from the guide (e.g. training tracks) must be treated as
  derivative and follow the same attribution logic, making clear to the end user what is
  "original OWASP" versus "AI-generated/adapted."

## 2. Personas

| Persona | Description | Main Need |
|---|---|---|
| **Program Captain (AppSec Lead)** | Responsible for creating/maintaining the champions program | Structure, metrics, reports for leadership |
| **Security Champion** | Developer with an interest in security, focal point on the team | Clear learning track, recognition, community |
| **CISO / Leadership** | Approves budget and priorities | Visibility into ROI and program maturity |
| **New program member** | Developer newly appointed as champion | Guided onboarding, knowing where to start |

## 3. Features

### 3.1 MVP (Phase 1)

**F1. Program Maturity Assessment**
- Structured questionnaire based on the 10 OWASP Manifesto principles.
- Maturity score per principle (e.g. 0-4, SAMM-like scale).
- Radar chart visualization (similar to SAMM).

**F2. Personalized Action Plan**
- From the score, AI generates a 3-6-12 month roadmap.
- Prioritizes principles with the lowest maturity.
- Based on the official OWASP checklists (recruitment, training, retention, etc.).

**F3. Training Track Generator**
- User provides: the team's tech stack (e.g. Java Spring, Node.js, Python/Django),
  experience level, available time/week.
- AI generates a study track with: prioritized topics (OWASP Top 10, ASVS relevant to
  the stack), suggested hands-on exercises (e.g. OWASP Juice Shop / WebGoat labs), a
  reinforcement quiz format.
- Exports to Markdown / PDF.

**F4. Checklist Library**
- All official OWASP Security Champions Guide checklists, browsable by principle and
  lifecycle phase (Attraction/Recruitment → Development/Retention).
- Progress tracking (checkbox) per organization.

**F5. Executive Report**
- AI generates a report in executive language (for CISO/leadership) from the maturity
  and progress data.
- Includes: current score, historical evolution, risks of not investing, comparison
  against industry benchmarks (when available).

### 3.2 Phase 2 (Post-MVP)

**F6. Quiz Engine / Gamification**
- Automatic quiz generation per topic (AI), with a per-organization leaderboard.
- Optional integration with CTF-style challenges (e.g. links to OWASP Juice Shop).

**F7. Community / Knowledge Sharing**
- A space for champions to share findings, questions, real-world cases (a simple forum
  or integration with Discord/Slack via webhook).

**F8. Multi-tenant / Multi-team**
- Support for multiple teams/squads within the same organization, with aggregated and
  per-team dashboards.

**F9. Integration with existing AppSec tools**
- Connect with SAMM and Threat Dragon already published in the portfolio, creating a
  "unified AppSec maturity dashboard."

### 3.3 Explicitly Out of Scope
- Not a full LMS platform (no video hosting, no formal certificates).
- Doesn't replace SAST/DAST — it's about people and process, not code.

## 4. Non-Functional Requirements

- **Open-source** (suggested license: Apache 2.0 or MIT for the code; CC BY-SA 4.0 for
  content derived from OWASP).
- **Self-hostable**: must run locally via Docker Compose for orgs that don't want to
  send data to external services.
- **Privacy**: maturity assessment data is sensitive (may expose internal weaknesses) —
  must not be publicly exposed by default.
- **Controllable AI cost**: user must be able to plug in their own API key
  (Anthropic/OpenAI) — no cost embedded for the project maintainer.
- **Browser-accessible**, responsive (also used by champions in informal contexts).

## 5. Technical Architecture (Suggestion)

### 5.1 Stack

| Layer | Suggested technology | Rationale |
|---|---|---|
| Frontend | React + Vite + Tailwind | Consistency with Threat Dragon/SAMM (if using a similar stack) |
| Backend | Node.js (NestJS) or Python (FastAPI) | Simple APIs, easy AI integration |
| Database | PostgreSQL | Structured data (scores, teams, progress) |
| AI | Anthropic (Claude) API via the user's own key | Generating tracks, reports, quizzes |
| Authentication | Simple auth (JWT) + optional SSO (OIDC) for corporate use | Self-host friendly |
| Deploy | Docker Compose (self-host) + optional static deploy (Vercel/Netlify) for a demo version | Eases adoption |
| OWASP content | Ingested via controlled scraping/parsing of public OWASP content (with a versioned local cache) | Avoids runtime dependency on external availability |

### 5.2 Data Model (high level)

```
Organization
 └── Team
      └── Champion (user)
      └── MaturityAssessment
           └── PrincipleScore (10x, one per Manifesto principle)
      └── TrainingTrack
           └── TrainingModule (AI-generated)
      └── ActionPlan
           └── ActionItem (checklist item, status)
      └── ExecutiveReport (generated snapshot)
```

### 5.3 Training Track Generation Flow (example prompt design)

1. Structured user input (stack, level, available time).
2. Context injected into the prompt: relevant excerpt from the official checklist +
   OWASP Top 10 / ASVS mapped to the stack.
3. Prompt for the AI to generate structured JSON (topics, order, resources, exercises).
4. Response schema validation before rendering.
5. Cache of generated tracks (avoid reprocessing identical combinations).

## 6. Product Success Metrics

## 8. Risks and Mitigations

| Risk | Mitigation |
|---|---|
| OWASP content changes/becomes outdated | Visible "last synced" indicator + periodic manual update process |
| Misuse of the maturity report (sensitive data exposed) | Private data by default, export under user control |
| Dependency on AI API cost | Support for multiple providers + "no AI" mode (static checklists work standalone) |
| Low adoption due to niche audience | Promote within the OWASP community (Slack, local chapters), possibility of submission as a related OWASP Project |
